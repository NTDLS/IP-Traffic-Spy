Filters Overview

A busy network produces far more packets than anyone wants to read. IP Traffic Spy filters let you choose which ones appear. There are two lists of filters, Include and Exclude, opened with I and E (or the Filters menu).

How a packet is judged

Each packet goes through these steps in order. If it fails any step it is not shown.

  1. Direction: the Broadcast / Inbound / Outbound Packets options on the Filters menu.
  2. Include filters: if there are no include entries, every packet passes. Otherwise the packet must match them (see below).
  3. Exclude filters: if the packet matches any exclude entry it is hidden, even if it matched an include entry.
  4. Protocol: the TCP / UDP / Other Protocols options on the Filters menu.

Include filters: any, or all

Include entries are arranged in five groups: source IPs, destination IPs, source ports, destination ports and advanced rules. By default a packet passes if it matches any entry in any group:

Source IP 10.0.0.0/8 + Destination port 443  shows packets from 10.x.x.x or to port 443.

Tick Require every filter group that has entries to match (AND) in the Include dialog, and a packet must match at least one entry in each group that has entries. The same two entries then show only packets from 10.x.x.x and to port 443.

For more control, an Advanced Rule combines any number of conditions with AND in a single entry, and can match either direction.

IP address entries

You typeMatches
192.168.1.5That one IPv4 address.
192.168.1.?IPv4 with ? wildcards, each standing for one digit. 10.0.?.? is 10.0.0.0 to 10.0.9.9; use CIDR for real ranges.
10.0.0.0/8A CIDR block: every address in the network. 192.168.1.77/24 is shown as 192.168.1.0/24.
2001:db8::1One IPv6 address.
fe80::/10An IPv6 CIDR block (prefix length 0 to 128).

Port entries

A single port such as 443, or an inclusive range such as 1024-65535 (0 to 65535). Ports only exist on TCP and UDP packets that carry their header, so ICMP packets, other protocols and fragments after the first never match a port entry. That means an include port filter hides them, while an exclude port filter leaves them alone.

Presets

  • Hide Network Noise adds exclude rules for DNS (53), NTP (123), NetBIOS (137-139), SSDP (1900), mDNS (5353), LLMNR (5355), multicast addresses (224.0.0.0/4), the broadcast address (255.255.255.255) and IGMP.
  • Web Traffic Only adds include rules for ports 80, 443, 8080 and 8443.

Presets are simply added to your existing filters; use Clear All Filters to start over.

Right-click filters

Select one or more rows, right-click, and choose Filters > Exclude or Include:

ItemAdds
Source IP / Port, Destination IP / PortAn entry for that exact value, in the matching list.
Conversation (Both Directions)A rule matching the two addresses in either direction: ip A and ip B.
Remote IP (Either Direction)A rule for the address at the other end (the one that is not this computer): ip A.
Remote Port (Either Direction)A rule for the remote end's port, e.g. port 443.
Remote Host (Either Direction)A rule for the remote host name, e.g. host example.com. Only available once the name is known.
ProtocolA rule for the packet's protocol, e.g. proto udp.

The status bar confirms what was added, and tells you if the filter already existed. Remove Filters Matching This Packet deletes every existing include and exclude entry that the selected packet matches - handy for undoing a filter without opening the dialogs.

Filters and the grid

  • Filters only affect packets that arrive after you change them. To tidy rows that are already in the grid use Filters > Apply Filters To Grid. This deletes the rows that would not be shown; it asks first.
  • The Matched By column shows which include entries let each packet through.
  • The status bar shows the filter count and how many packets have been hidden.

Remembering and sharing filters

  • Your filters are saved automatically when you exit and restored the next time you start. They are stored for the current Windows user (HKEY_CURRENT_USER\Software\NetworkDLS\IP Traffic Spy\Filters).
  • Filters > Save Filters... writes them to a .ipsf text file and Load Filters... reads one back (replacing the current filters). Keep a file per situation - "web debugging", "DNS only" - and share them with others. A file that is not a filter file is rejected without changing anything.
  • Clear All Filters empties both lists and the AND option.
