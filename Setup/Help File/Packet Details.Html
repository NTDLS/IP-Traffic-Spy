Packet Details

Double-click a row in the grid, or right-click it and choose Details, to open Packet Details. It shows one packet in two panes: a decoded pane on top and the packet bytes below. While the dialog is open capture is paused. The dialog can be resized, minimized or maximized.

Moving between packets

The Prev and Next buttons (keyboard: Alt+P and Alt+N) step through the grid's rows without closing the dialog. The row selected in the grid follows along, so you are left where you were looking when you close it. The title bar and the box under the buttons show which packet you are on.

The decoded pane

Switch it on or off with Decoded headers. It starts with what the grid knows (when it was captured, direction, the addresses and host names, and what include filter matched) and then decodes the packet:

LayerWhat you see
IPv4Header length, type of service (DSCP/ECN), total length, identification, flags (DF/MF), fragment offset, TTL, protocol, the header checksum and whether it is valid, source and destination, and any options.
IPv6Traffic class, flow label, payload length, next header, hop limit, source and destination, and each extension header (hop-by-hop, routing, fragment with its offset and identification, destination options, authentication).
TCPPorts (with the service name, e.g. 443 (https)), sequence and acknowledgment numbers, header length, flags, window, checksum, urgent pointer, and the options: maximum segment size, window scale, SACK, timestamps and more.
UDPPorts, length and checksum.
ICMP / ICMPv6Type and code in words (echo request, destination unreachable, neighbor solicitation, ...), checksum, and the identifier and sequence for echo messages.
DNSTransaction id, opcode, flags, response code and counts; every question; and the answer, authority and additional records including the address, name, MX, SRV, TXT and SOA data. Used for UDP and TCP port 53, and mDNS / LLMNR.
HTTPThe request or status line and every header line, and how many body bytes are in this packet. Only unencrypted HTTP can be read.
TLSThe records in the packet. For a ClientHello and ServerHello: version, the cipher suites offered or chosen, and the extensions, including the server name (SNI), supported versions, groups and key shares and the ALPN protocols. The data after the handshake is encrypted and is shown only as "Application Data".

Fields that continue in a following packet (a TLS handshake or HTTP headers split across packets) are labelled as such. Packets that were truncated or damaged show what could be decoded.

Checksum note: packets that your own computer sends commonly show an invalid IPv4 header checksum. This is normal: network adapters fill the checksum in after the packet has been captured ("checksum offload").

The bytes pane

  • HEX: a hex dump: offset, 16 bytes per line (in two groups of eight) and an ASCII column on the right where anything that is not printable shows as a dot.
  • Printable ASCII: only the printable characters of the data.
  • Raw: the data as is, with zero bytes shown as spaces.
  • Omit Packet header? (on by default): start the bytes at the data after the IP and TCP/UDP headers. Untick it to see the whole packet from the first byte of the IP header; hex offsets then count from the start of the packet.
  • Wrap text?: wrap long lines instead of scrolling sideways.
