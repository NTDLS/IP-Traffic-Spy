Known Issues & Limitations

IP Traffic Spy would not have been released if there were any "known" bugs, but there are some limits that come from how Windows allows programs to capture traffic:

  • Administrator rights are required to capture packets.
  • One adapter at a time. Only the adapter you connect to is watched (both its IPv4 and IPv6 traffic).
  • Loopback traffic (programs talking to each other on the same computer) is generally not visible.
  • IPv6 headers. Windows may deliver IPv6 packets without their header. The program detects this: it rebuilds the addresses but cannot know the protocol, ports or flags, so those packets show only addresses and size.
  • Switched networks only deliver your own traffic and broadcasts/multicasts to your adapter.
  • Packets are not recorded while paused or while a dialog is open.
  • Encrypted traffic cannot be read. The program shows connection details (addresses, ports, TLS server name, handshake parameters) but never decrypts anything.
  • Only individual packets are shown. HTTP headers or TLS handshakes that span several packets are not reassembled, and text split across packets is not found by contains.
  • Checksums on packets your computer sends often look invalid due to checksum offload.
  • Fragments: only the first fragment of a datagram has ports, flags and readable data. Later fragments are shown with ports 0 and Frag = Yes.
  • Host name rules using wildcards depend on reverse DNS, which often does not match the name you know a site by.
  • Size limits. The grid keeps up to 100,000 rows or 512 MB of packet data. Older rows are discarded.
  • The program needs a recent version of Windows; it will not run on old systems such as Windows 95.

If you have found an error in IP Traffic Spy please see Reporting Bugs under the "Contact" section in this help file.
