Troubleshooting

Nothing shows in the grid

  • Are you running as administrator? Without it Windows refuses to open the capture socket. Look at the left of the status bar for an error message, then restart the program as an administrator.
  • Is the status bar saying "Connected to ..."? If it says (Not Connected) use File > Change Connection.
  • Did you pick the right adapter? If you have a wired connection, Wi-Fi, a VPN and virtual adapters, only the one you chose is watched.
  • Is it paused? The title bar says "(Paused)". Press the Space Bar.
  • Are filters hiding everything? Check the right of the status bar. Any include filter hides everything that does not match it. Try Filters > Clear All Filters. Also check that TCP, UDP, Other Protocols and the Broadcast / Inbound / Outbound options on the Filters menu are ticked.
  • Host name rules: if you have a host rule, packets are shown only once the name is known - see Host names.
  • Security software can interfere with packet capture. Try allowing the program.

I cannot see another computer's traffic

You only see what reaches your network adapter. On a switched network that is your own traffic plus broadcasts and multicasts. To see other machines' traffic you need to run the program on the machine in question, or on a switch port set up to mirror ("span") the traffic.

I cannot see traffic between programs on this computer

Traffic over the loopback address (127.0.0.1 / ::1) does not usually pass through your network adapter, and is generally not visible.

Host names show "..." or are blank

  • ... means the lookup is still waiting - watch the Backlog in the status bar. Lookups run a few at a time, and slow DNS servers or many new addresses can make them queue.
  • A blank name means the address simply has no reverse DNS name. This is very common for home and mobile networks.
  • Host names depend on your DNS server. If your DNS is unreachable, lookups fail.
  • Check that Actions > DNS Lookups is ticked. With it off, new addresses are never looked up.

IPv6 packets show no ports or protocol

Windows does not always supply the IPv6 header on capture sockets. When it does not, the program tells you in the status bar (IPv6 protocol/ports unavailable) and IPv6 rows show their addresses and size only. IPv4 is not affected. See Known Issues.

A packet I sent has an invalid checksum

This is normal, it is "checksum offload". See Packet Details.

The Text column looks like gibberish

The data is probably encrypted (TLS/HTTPS, SSH, VPN) or compressed or binary. The program shows only printable characters there. Open Packet Details and use the HEX view for the exact bytes. For TLS the connection's server name is shown in the Text column of the opening packet.

Packets are missing

While the program is paused, or a dialog is open, packets are not recorded. Very heavy traffic can also overflow the operating system's small capture buffer, in which case some packets are dropped - use filters to keep the volume down.

The grid is empty after changing a filter

You may have used Apply Filters To Grid, which deletes rows that do not match. Otherwise changing filters affects only new packets.
