Advanced Rules

An Advanced Rule is a single filter entry made of one or more terms. A packet matches the rule only when all of its terms match. The word and between terms is optional and just makes a rule easier to read. Each rule in the list is a separate alternative: a packet needs to match just one of the rules. Keywords are not case sensitive.

Hover over the Advanced Rules section of the Include or Exclude dialog to see this reference as a tool tip.

Terms

TermMatches
src <ip>The source IP address.
dst <ip>The destination IP address.
ip <ip>Either the source or the destination address. Use two ip terms to follow a conversation in both directions.
sport <port>The source port.
dport <port>The destination port.
port <port>Either port.
proto <protocol>The IP protocol (for IPv6, the protocol after any extension headers).
flags <list>TCP flags. Every listed flag must be set; put ! in front of a flag to require it to be clear.
shost <name>The host name of the source.
dhost <name>The host name of the destination.
host <name>The host name of either end.
contains <text>The packet data (after the headers) contains the text, ignoring case.

Values

Used withValue
src dst ipAn IP address (192.168.1.5), IPv4 wildcard (10.0.?.?), CIDR block (10.0.0.0/8, fe80::/10) or IPv6 address (2001:db8::1).
sport dport portA port (443) or an inclusive range (1024-65535).
protoA name: tcp udp icmp icmpv6 igmp gre esp ah sctp, or a protocol number from 0 to 255.
flagsA comma separated list of fin syn rst psh ack urg ece cwr, e.g. syn,!ack. Only TCP packets have flags.
shost dhost hostA host name. See Host names below.
containsThe text to find. Put it in "double quotes" if it contains spaces: contains "user-agent: curl".

Examples

RuleWhat it finds
port 53DNS traffic in either direction.
ip 10.1.2.3 and ip 10.1.2.9Everything between those two machines, both directions.
src 192.168.0.0/16 and dport 1024-65535Traffic from the local network to high ports.
proto tcp and flags syn,!ack and dport 22Incoming SSH connection attempts (SYN without ACK).
proto tcp and flags rstConnection resets.
host *.microsoft.comAnything to or from a Microsoft host.
host example.com and port 443HTTPS traffic to or from example.com.
proto icmpv6IPv6 neighbor discovery, ping and friends.
contains "password"Unencrypted packets that mention a password.

If a rule has a mistake (an unknown term, a missing value, a bad address or port) the dialog tells you what is wrong when you press Add, and the rule is not added.

Host names

  • A plain name such as example.com is looked up for you. The rule then matches that site's IP addresses (IPv4 and IPv6), and also any address whose reverse DNS name contains the text. The lookup repeats every few minutes because sites change addresses, and a failed lookup is retried after about half a minute.
  • A name with wildcards (* for any text, ? for one character), such as *.example.com, is compared with the address's reverse DNS name only. The name is filled in by reverse DNS shortly after an address is first seen, so the first few packets of a brand new address may be missed by a wildcard rule.
  • Reverse DNS names belong to the address and often differ from the name you typed in a browser (large sites, content networks and hosting companies commonly have unrelated reverse names). Use a plain name where you can.
  • Host names are looked up for every address seen, even those your filters hide.

Notes

  • A rule needs at least one term. port, sport and dport terms never match packets without ports (ICMP, other protocols, non-first fragments); flags never matches non-TCP packets.
  • contains searches the data after the IP and TCP/UDP headers of that one packet. Encrypted (TLS) traffic will not contain readable text, and text split across two packets will not be found.
  • To match the Matched By column back to a rule, look for the rule text shown there with the prefix Rule:.
  • Rules are kept exactly as you typed them. Use Remove Filters Matching This Packet or the dialog's Delete button to remove them.
